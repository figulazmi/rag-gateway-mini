## CHUNK 3: Qdrant dashboard visualize patch GKt variable dense vector

### Context
Qdrant v1.17.1 on VM B1 (192.168.18.199). Collection knowledge_v2 uses named vectors (dense+sparse). Dashboard has two separate visualization routes: /graph and /visualize, each with its own default editor template variable in the minified JS.

### Problem
Patching Hnn variable in index-C-wxiiEX.js added "using": "dense" to /graph route but NOT to /visualize route. Dashboard Visualize panel (/collections/knowledge_v2/visualize) still showed {"limit": 500} without "using": "dense" even after previous Hnn patch and container restart. Additionally, after editing the file on host, Qdrant HTTP server served stale content from memory cache until container was restarted.

### Solution
Two separate variables must be patched in index-C-wxiiEX.js:
1. Hnn -- default template for /graph route (qnn component)
2. GKt -- default template for /visualize route (YKt component)

Patched GKt with Python replace on host file, then restarted Qdrant container to flush HTTP static asset memory cache. After restart, curl confirmed GKt served with "using": "dense".

### Key Facts
- /visualize route uses YKt component with GKt template variable; /graph route uses qnn component with Hnn template variable -- both must be patched independently.
- Qdrant HTTP server caches static assets in memory -- bind mount file changes on host are NOT reflected until container restart (docker compose -p ai-stack restart qdrant).
- GKt template literal is at byte offset ~5227233 in index-C-wxiiEX.js (v1.17.1). Pattern to find: const GKt=\`\n\n// Try me!\n\n{\n  "limit": 500\n}\n\n// Specify request parameters
- "using": "dense" is mandatory for knowledge_v2 because the collection has no default vector -- Qdrant cannot infer which named vector to use without explicit specification.
- Browser cache (Firefox/Edge) can persist even across hard refresh and private windows if Qdrant serves JS with long max-age. DevTools "Disable Cache" + F5 forces re-fetch.
