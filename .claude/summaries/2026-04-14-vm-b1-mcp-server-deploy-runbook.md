## CHUNK 1: Update MCP Server JS File on VM B1 via SCP

### Context

The qdrant-knowledge MCP server runs as Node.js on VM B1 (192.168.18.169), spawned
per-connection by ~/.claude/claude-mcp-connect.ps1 on the Windows laptop. The server
file is at /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js. The /opt/
directory is root-owned, but the JS file itself is owned by figulazmi (mode 0664),
so sudo is NOT needed to overwrite the file directly.

### Prerequisites

- SSH key-based access to figulazmi@192.168.18.169 (no password prompt).
- Updated JS file ready locally.
- scp available (Windows Git Bash or native OpenSSH).

### Steps

1. Backup existing file to home dir (writable without sudo):
   ssh figulazmi@192.168.18.169 "cp /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js ~/qdrant-mcp-server.js.bak"

2. SCP new file to /tmp/ on VM B1 (always writable):
   scp "C:/path/to/new-server.js" figulazmi@192.168.18.169:/tmp/qdrant-mcp-server-new.js

3. Copy from /tmp/ to destination (no sudo needed - file is figulazmi-owned):
   ssh figulazmi@192.168.18.169 "cp /tmp/qdrant-mcp-server-new.js /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js"

4. Verify deployment:
   ssh figulazmi@192.168.18.169 "grep -E 'COLLECTION|version' /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js | head -5"

### Verification

- grep COLLECTION should return the new collection name.
- No manual process restart needed: MCP spawns fresh per Claude Code session.
- Test in next session by loading tool schema and calling search_knowledge.

### Key Facts

- /opt/mcp-servers/qdrant-knowledge/ directory is root-owned; cannot create new files there without sudo.
- qdrant-mcp-server.js file itself is owned by figulazmi (0664) - can be overwritten via cp without sudo.
- Critical workaround: scp to /tmp/ first, then cp from /tmp/ to /opt/ as figulazmi user.
- Backup must go to ~/ (home dir), not /opt/, since home dir is fully writable.
- MCP lifecycle: spawned by PowerShell per session, not a persistent systemd service.

### Troubleshooting

- "sudo: terminal required" when trying sudo cp over SSH: do not use sudo via non-interactive SSH.
  Use the /tmp/ workaround instead.
- "Permission denied" on direct scp to /opt/: directory is root-owned. Always scp to /tmp/ first.
- MCP tool shows unavailable after killing old process: normal, reconnects in next Claude Code session.
