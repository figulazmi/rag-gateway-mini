## CHUNK 1: Update qdrant-mcp-server.js on VM B1

### Context

The `qdrant-knowledge` MCP server runs as a Node.js process on VM B1
(`192.168.18.169`), spawned per-connection by `~/.claude/claude-mcp-connect.ps1`
on the Windows laptop. The server file lives at
`/opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js` on VM B1.
The directory is owned by `root` but the JS file itself is owned by `figulazmi`
(mode `0664`) — so `sudo` is not needed for the file, but `cp` to `/opt/` requires
writing through the user-owned file directly.

### Prerequisites

- SSH key-based access to `figulazmi@192.168.18.169` (no password prompt).
- Updated JS file ready locally.
- `scp` available (Windows Git Bash or native OpenSSH).

### Steps

1. Write updated JS file locally (e.g., `scripts/qdrant-mcp-server-v2.js`).
2. Backup existing file on VM B1:
   ```bash
   ssh figulazmi@192.168.18.169 "cp /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js ~/qdrant-mcp-server.js.bak"
   ```
3. SCP new file to VM B1 temp location:
   ```bash
   scp "C:/path/to/qdrant-mcp-server-v2.js" figulazmi@192.168.18.169:/tmp/qdrant-mcp-server-new.js
   ```
4. Copy from temp to destination (no sudo needed — file is owned by figulazmi):
   ```bash
   ssh figulazmi@192.168.18.169 "cp /tmp/qdrant-mcp-server-new.js /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js"
   ```
5. Verify deployment:
   ```bash
   ssh figulazmi@192.168.18.169 "grep -E 'COLLECTION|version' /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js | head -5"
   ```
6. No manual process restart needed — MCP server is spawned fresh per-connection by PowerShell script.

### Verification

- New session in Claude Code will spawn fresh MCP process using updated file.
- Confirm with: `grep COLLECTION /opt/mcp-servers/qdrant-knowledge/qdrant-mcp-server.js`
- Test search via `mcp__qdrant-knowledge__search_knowledge` after loading schema with ToolSearch.

### Key Facts

- `/opt/mcp-servers/qdrant-knowledge/` directory is owned by `root` — cannot create new files without sudo.
- `qdrant-mcp-server.js` file itself is owned by `figulazmi` (mode 0664) — can be overwritten directly via `cp`.
- Workaround: scp to `/tmp/` first, then `cp` from `/tmp/` to destination as `figulazmi` user.
- MCP process lifecycle: spawned by PowerShell `claude-mcp-connect.ps1` per Claude Code session — no systemd service.
- Backup should go to `~/` (home dir) not `/opt/` since home dir is fully writable.

### Troubleshooting

- `sudo: a terminal is required` when trying `sudo cp`: do not use sudo via SSH non-interactive session.
  Use the `/tmp/` workaround above instead.
- `Permission denied` on direct copy to `/opt/mcp-servers/qdrant-knowledge/`: directory is root-owned.
  Always copy to `/tmp/` first.
- MCP tool shows as unavailable in current session after process kill: normal behavior.
  Reconnects automatically in next Claude Code session.
