## CHUNK 1: Qdrant Visualize Error - Default Vector Not Defined

### Context

knowledge_v2 collection on VM B1 uses named vectors: "dense" (768-dim COSINE) and
"sparse" (djb2 IDF). Unlike the legacy "knowledge" collection which had an unnamed
default vector, knowledge_v2 has NO default vector. Every API operation must
explicitly declare which vector to use via the `using` parameter.

### Problem

Qdrant Dashboard Visualize feature returned:
"Please select a valid vector name (by `using`), default vector is not defined"
when attempting to visualize the knowledge_v2 collection. The dashboard was
sending the visualize request without specifying a vector name.

### Solution

All Qdrant API calls on named-vector collections must include `using: "dense"` (or
"sparse") explicitly. Created `scripts/qdrant-visualize.sh` which calls
`POST /collections/knowledge_v2/points/visualize` with `"using": "dense"` in the
request body. Script also accepts `--project` filter and saves output to
`.claude/reports/visualize-YYYYMMDD.json`.

### Key Facts

- knowledge_v2 has NO default/unnamed vector — `using` is mandatory for every API call.
- Qdrant Dashboard Visualize sends requests without `using` if no vector is selected in UI — select "dense" from dropdown before clicking Visualize.
- The error text "default vector is not defined" is Qdrant's signal that `using` is missing.
- Fix applies to all endpoints: `/points/visualize`, `/points/recommend`, `/points/query`, `/points/search`.

### Code / Commands

```bash
# Fix: always pass using="dense"
curl -X POST http://localhost:6333/collections/knowledge_v2/points/visualize \
  -H "api-key: YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"limit": 100, "using": "dense"}'

# Or use the helper script
bash scripts/qdrant-visualize.sh --project homelab --limit 50
```

## CHUNK 2: Qdrant Graph HTTP 400 - Not Existing Vector Name Error

### Context

Same knowledge_v2 collection on VM B1 (named vectors: "dense" + "sparse").
The graph/explore feature in Qdrant uses the `/points/recommend` endpoint to
find semantically similar documents from a seed point.

### Problem

Graph feature returned HTTP 400:
`{"status":{"error":"Wrong input: Not existing vector name error: "},"time":0.000165159}`
Note the trailing empty string after the colon — this means `using` was set to `""`
(empty string) rather than a valid vector name. The graph request was built without
populating the `using` field.

### Solution

The `/points/recommend` endpoint for named-vector collections requires `using: "dense"`.
Created `scripts/qdrant-graph.sh` which calls the recommend endpoint with
`"using": "dense"` and accepts `--point-id` or `--random` to pick a seed point.
Script auto-fetches a random point via `/points/scroll` if no ID is given.

### Key Facts

- Error "Not existing vector name error: " (empty trailing string) means `using` field is empty string, not missing entirely.
- Qdrant recommend (graph explore) endpoint: `POST /collections/{name}/points/recommend` with `using` required.
- `/points/scroll` does NOT require `using` — it retrieves payload/IDs only, not vectors.
- `with_vectors: true` in scroll DOES require `using` for named-vector collections.

### Code / Commands

```bash
# Fix: explicit using="dense" in recommend body
bash scripts/qdrant-graph.sh --random --project homelab

# Or with specific seed point
bash scripts/qdrant-graph.sh --point-id "abc-123-uuid" --limit 10
```
