## CHUNK 1: Status Field Default Test

### Context
End-to-end sanity check for the updated n8n workflow ingest-knowledge-v2.json on VM B1. The workflow now sets payload.status = "implemented" by default when rag merge pushes a chunk through the webhook at http://192.168.18.169:5678/webhook/knowledge-ingest into Qdrant collection knowledge_v2.

### Problem
Existing chunks in knowledge_v2 were missing the status payload field, which blocked the MCP v2 server from filtering implemented-only results via include_planned=false. The workflow Prepare Qdrant Point node previously had no status key in its payload object.

### Solution
Added an ALLOWED_STATUS whitelist and a status field in the Prepare Qdrant Point node payload, defaulting to implemented when the input does not explicitly set it to planned or deprecated. This test chunk validates the pipeline end-to-end from rag add through push-to-qdrant.sh into Qdrant, and confirms the new field materializes in the stored point.

### Key Facts
- Workflow JSON lives at scripts/n8n-workflows/ingest-knowledge-v2.json in rag-gateway-mini repo
- Status whitelist is implemented, planned, deprecated with implemented as the safe default fallback
- Verification query uses Qdrant scroll with filter topic equals Status Field Default Test
- MCP server filter include_planned=false depends on this payload field existing on every point
- Backfill strategy is POST to points/payload with filter is_empty on key status, idempotent and safe to re-run
