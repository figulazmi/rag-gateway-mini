## CHUNK 1: Fix n8n knowledge_v2 ingest errors
<!-- rag_chunk_meta chunk_type=debug tags=[homelab, vm-b1, n8n, qdrant, ollama, rag-capture] -->

### Context
The knowledge_v2 n8n workflow receives payloads from push-to-qdrant.sh during rag merge and writes embedded chunks into Qdrant collection knowledge_v2.
### Problem
rag merge returned HTTP 200 at the webhook layer, but n8n execution history showed errors. Root causes were a stale Qdrant API key expression in the Qdrant upsert node, invalid n8n prompt expressions in the Ollama HTTP node, and a broken unrelated workflow called Capture Chat Insight that spammed activation errors.
### Solution
Unpublish the broken Capture Chat Insight workflow. Patch knowledge_v2 so Qdrant Upsert uses the active Qdrant API key, Validate and Clean emits a prompt field equal to embed_content, and Ollama nomic-embed-text reads that prompt field. Publish the workflow, set active=1, restart n8n with docker compose, then verify n8n execution_entity status shows success for new webhook executions.
### Key Facts
- Webhook HTTP 200 does not prove n8n workflow success; check execution_entity.status in the n8n SQLite database.
- Qdrant writes can fail with 401 Invalid API key or JWT even when the webhook response is 200.
- n8n workflow changes may need publish plus container restart before production webhook execution uses the patched version.
- Smoke-test points tagged smoke-test must be deleted from Qdrant after validation.
### Code
n8n DB path: /var/lib/docker/volumes/ai-stack_n8n_data/_data/database.sqlite
Success check: select id,workflowId,status,mode,startedAt,stoppedAt from execution_entity where workflowId="MFqzRjRuiXRgbGgl" order by id desc limit 5;
Cleanup: POST /collections/knowledge_v2/points/delete with filter tags match any ["smoke-test"].
