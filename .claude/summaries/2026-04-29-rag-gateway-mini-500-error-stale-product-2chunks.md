## CHUNK 1: rag-gateway-mini 500 error stale Production config wrong IP collection
<!-- rag_chunk_meta chunk_type=debug tags=[homelab, vm-b1, rag-gateway, dotnet, config, docker] -->

### Context
rag-gateway-mini runs on VM B1 (192.168.18.199:5200) via Docker. Production config is mounted as a volume from `/opt/homelab/ai-stack/rag-gateway-mini/appsettings.Production.json` into `/app/appsettings.Production.json`.

### Problem
All `/rag/search` and `/rag/debug` requests returned HTTP 500. Error in container logs: `HttpRequestException` connecting to `192.168.18.169:11434` (Ollama) and `192.168.18.169:6333` (Qdrant). The production config was a stale file from before the VM IP migration, never updated.

### Solution
Updated `/opt/homelab/ai-stack/rag-gateway-mini/appsettings.Production.json` with correct values, then ran `docker compose up -d --build` to also pick up code changes (deployed binary was stale, using old `ExecuteSearchAsync` instead of `ExecuteQueryAsync` with Query API + RRF fusion).

### Key Facts
- Production config path (from docker-compose.yml volumes): `/opt/homelab/ai-stack/rag-gateway-mini/appsettings.Production.json` -- NOT `/opt/rag-gateway/appsettings.Production.json`
- Four stale values in old config: OllamaBaseUrl `.169` -> `.199`, QdrantBaseUrl `.169` -> `.199`, QdrantCollection `knowledge` -> `knowledge_v2`, ScoreThreshold `0.55` -> `0.35`
- Missing hybrid search fields that must be present: `DenseVectorName`, `SparseVectorName`, `EnableHybridSearch`, `HybridPrefetchLimit`, `SparsePrefetchLimit`, `SparseScoreThreshold`, `FusionMethod`
- Deployed binary version mismatch: if container was never rebuilt after code refactor, `ExecuteSearchAsync` (old) vs `ExecuteQueryAsync` (new Query API) causes 400 from Qdrant
- Always rebuild after code changes: `cd /opt/homelab/ai-stack/rag-gateway-mini/src && sudo docker compose up -d --build`
- Verification: `curl -s -X POST http://localhost:5200/rag/search -H "Content-Type: application/json" -d '{"query":"...","project":"homelab"}'`

## CHUNK 2: rag-gateway-mini RagSearchRequest full parameter surface chunk_type feature_slug
<!-- rag_chunk_meta chunk_type=reference tags=[homelab, vm-b1, rag-gateway, dotnet, api, retrieval] -->

### Context
rag-gateway-mini exposes POST `/rag/search` and POST `/rag/debug` endpoints. Scalar UI only shows `query` and `project` in the auto-generated example body because optional nullable fields are omitted from the schema example.

### Problem
Users assume only `query` and `project` are supported because Scalar does not show optional nullable fields in its generated request body example.

### Solution
All four fields are fully implemented in `RagSearchRequest.cs` and wired through `RagSearchService` -> `QdrantVectorSearchClient.ExecuteQueryAsync`. Add them manually in Scalar or any HTTP client.

### Key Facts
- Full request body: `{"query":"...","project":"homelab","chunk_type":"debug","feature_slug":"some-doc-id"}`
- `chunk_type` maps to Qdrant payload field `chunk_type`; valid values: `debug`, `feature`, `runbook`, `pattern`, `decision`, `reference`, `implementation-spec`
- `feature_slug` maps to Qdrant payload field `doc_id`; retrieves all chunks from a specific ingestion session
- `/rag/debug` applies NO score threshold and NO filters (applyFilter=false) -- returns all raw Qdrant results for diagnostics regardless of chunk_type or feature_slug passed
- `/rag/search` applies filters AND ScoreThreshold=0.35; use `/rag/debug` first to inspect raw scores when results are missing
- Source files: `src/Application/DTOs/RagSearchRequest.cs`, `src/Infrastructure/AI/QdrantVectorSearchClient.cs:ExecuteQueryAsync`
