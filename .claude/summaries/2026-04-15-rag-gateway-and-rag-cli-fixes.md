## CHUNK 1: rag-gateway-mini Port and Health Endpoint Status

### Context
rag-gateway-mini is an ASP.NET Core 9 API deployed via Docker on VM B1
(192.168.18.169) as the RAG gateway for the homelab AI stack. Deployment
and verification instructions live in the repo CLAUDE.md.

### Problem
Documentation in CLAUDE.md instructs operators to verify deployment with
`curl http://localhost:5200/health`, but the actual code does not map any
health endpoint. This is docs drift that will cause verification failure.

### Solution
Treat port 5200 as HTTP plain (no TLS at the container). For now, use the
Scalar UI or OpenAPI doc as liveness proxy until a real health endpoint is
added. Planned fix: add `app.MapHealthChecks("/health")` in Program.cs.

### Key Facts
- rag-gateway-mini container listens on http://+:5200 via ASPNETCORE_URLS in src/docker-compose.yml
- No TLS on port 5200 — HTTPS only active in local launchSettings.json (port 7200)
- Program.cs does NOT call MapHealthChecks and no HealthController exists as of 2026-04-14
- CLAUDE.md references /health endpoint that is not implemented — docs drift
- Working liveness probes: GET /scalar/ (UI) and GET /openapi/v1.json
- RagController is mounted at route "rag" — no /api prefix
- Public URL from LAN: http://192.168.18.169:5200/scalar/

## CHUNK 2: Redeploy rag-gateway-mini to VM B1 from Laptop

### Context
rag-gateway-mini is deployed as a Docker container on VM B1 (192.168.18.169)
at /opt/homelab/ai-stack/rag-gateway-mini. Secrets live outside the repo at
/opt/rag-gateway/appsettings.Production.json. Redeploy is a pull-and-rebuild
flow initiated from the developer laptop after pushing to main.

### Problem
Operator needs a deterministic step-by-step to ship changes from laptop main
to the live container on VM B1 without touching production secrets, with
verification and rollback steps.

### Solution
Seven-step flow: push on laptop, SSH to VM B1, git pull, docker compose up
--build, verify container and logs, smoke test endpoints from LAN, and
rollback via git reset hard plus rebuild if verification fails.

### Key Facts
- Repo path on VM B1 is /opt/homelab/ai-stack/rag-gateway-mini — pull from that directory
- Build context in docker-compose.yml is .. so repo root is required for Directory.Packages.props
- Rebuild command is `docker compose up -d --build` run inside the src subfolder
- Health endpoint /health is not implemented — smoke test uses /scalar/ or /openapi/v1.json
- Container listens on http://+:5200 plain HTTP, no TLS
- Rollback is `git reset --hard <sha>` followed by `docker compose up -d --build`
- appsettings.Production.json at /opt/rag-gateway/ must never be modified during redeploy
- SSH user on VM B1 is figulazmi

## CHUNK 3: rag_capture.py Cross-Platform Posix Path Output

### Context
The rag CLI (rag_capture.py) generates push reminders after rag merge and rag remind,
printing a bash command with the merged summary file path. Users copy this command
into git bash to push the summary to Qdrant knowledge_v2 collection on VM B1.

### Problem
On Windows, Path objects stringify with backslashes. The printed command looked like
bash ~/scripts/push-to-qdrant.sh C:\Users\Clandesitine\source\repos\... . When pasted
into git bash, backslashes were interpreted as escape characters, collapsing the path
into C:UsersClandesitinesourcerepos... and producing File not found error.

### Solution
Added a posix(p) helper that wraps Path(p).as_posix(), which forces forward slashes
on Windows and is a no-op on Linux/macOS. Applied to five print sites that output
paths intended for bash: print_push_reminder two call sites, cmd_merge success line,
and cmd_remind two call sites. Internal Path operations for file IO were left alone
since Python handles separators transparently at the filesystem layer.

### Key Facts
- Python Path.as_posix() converts backslashes to forward slashes on Windows only
- Git bash treats backslash as escape character, not path separator
- The CLI entrypoint lives at two locations that can drift: ~/.local/bin/rag and the repo copy at scripts/rag-capture-v2/rag_capture.py
- Only printed paths need posix conversion, not internal Path operations
- Bash on Windows accepts drive-letter paths with forward slashes like C:/Users/...
- Fix verified with rag remind showing forward-slash output after edit

### Code
\`\`\`python
def posix(p) -> str:
    return Path(p).as_posix()

print(f"    bash {push_script} {posix(output_path)}")
\`\`\`
