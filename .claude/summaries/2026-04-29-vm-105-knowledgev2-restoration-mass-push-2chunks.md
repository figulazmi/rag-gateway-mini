## CHUNK 2: knowledge to knowledge_v2 migration via migrate-to-hybrid.py
<!-- rag_chunk_meta chunk_type=runbook tags=[homelab, vm-b1, qdrant, migration, knowledge-v2, hybrid-search] -->

### Context
Qdrant collection migration from old dense-only knowledge collection to knowledge_v2
with hybrid named vectors (dense + sparse BM25 djb2). Script migrate-to-hybrid.py was
created and run on VM B1 to copy existing embeddings directly, bypassing n8n pipeline.

### Problem
120 summary files existed as knowledge points in old collection. knowledge_v2 needed
these points with sparse vectors added. Full n8n re-embed would take 3-7 minutes and
require contextual retrieval prepend consistency check.

### Solution
Added --limit N flag to migrate-to-hybrid.py (Opsi A: break after N migrated, not slice
source). Tested with --limit 5: result 1:1 (5 migrated, knowledge_v2 7 to 12). Full
migration: 132 migrated, 2 skipped (project rag-gateway), 5 skipped (already existed
from test), 0 errors. knowledge_v2 went from 12 to 144 points.

Script copies dense vector from knowledge as-is and computes sparse vector client-side
via djb2. Pushes directly to Qdrant REST API -- no n8n, no re-embedding.

### Key Facts
- --limit flag guarantees 1:1: counts migrated points, breaks after N successful writes
- Dense vectors are old-style (raw content, no contextual prepend) -- consider Opsi 2 if NDCG degrades
- Script path: ~/scripts/migrate-to-hybrid.py -- runs ON VM B1 (QDRANT_URL=localhost:6333)
- Script must be scp'd to VM B1 before run: it does not exist there by default
- WARNING in RAG_V2_ROADMAP.md P1.2 section flags this for re-embed if retrieval regresses
