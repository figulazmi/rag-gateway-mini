## CHUNK 1: Fix rag pipeline reliability: qdrant_url wrong IP auto_push silent exception cmd_push_pending retry
<!-- rag_chunk_meta chunk_type=debug tags=[homelab, vm-b1, python, rag-pipeline, reliability, push-queue, fixed] -->

### Context
RAG pipeline on Windows laptop uses rag_capture.py (push-pending, auto_push) and push-to-qdrant.sh to push knowledge chunks to Qdrant on VM B1. Three reliability issues found during audit.
### Problem
Three bugs in pipeline reliability: (1) ~/.rag_config.json had qdrant_url=192.168.18.169:6333 (wrong IP, was .169 not .199). Not used by active code but risky if code reads it in future. (2) auto_push() caught FileNotFoundError and TimeoutExpired with bare except+pass, silently swallowing the error before queuing -- user could not tell WHY a push was queued. (3) cmd_push_pending() used except (FileNotFoundError, TimeoutExpired): break -- meaning TimeoutExpired aborted ALL remaining retries instead of just the current attempt, defeating the exponential backoff logic.
### Solution
Three targeted fixes: (1) ~/.rag_config.json qdrant_url updated to 192.168.18.199:6333 (correct IP). (2) auto_push() split except into separate handlers: FileNotFoundError prints "bash not found" message, TimeoutExpired prints "timed out, queuing" message -- both then fall through to queue the file. (3) cmd_push_pending() split except: FileNotFoundError still breaks (retrying is pointless), TimeoutExpired now continues (allows remaining backoff retries 2s/4s/8s to proceed).
### Key Facts
- qdrant_url in ~/.rag_config.json is not read by current push path (push-to-qdrant.sh does own network detection) but should be correct for hygiene.
- push-to-qdrant.sh exit code = FAIL_COUNT (number of failed chunks). auto_push queues the WHOLE file when exit != 0. Qdrant upsert is idempotent so re-pushing already-pushed chunks is safe.
- cmd_push_pending retries: 4 total attempts (delay 0s/2s/4s/8s). Still-failing files stay in ~/.rag_push_queue for next run.
- File location: C:/Users/Clandesitine/scripts/rag-capture-v2/rag_capture.py (Windows laptop, not in git repo).
- TimeoutExpired in auto_push is separate from cmd_push_pending -- auto_push has no retry loop, any exception goes to queue.
