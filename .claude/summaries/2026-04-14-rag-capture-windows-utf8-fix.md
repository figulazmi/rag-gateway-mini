## CHUNK 1: rag_capture.py Windows cp1252 Crash and Mojibake Fix

### Context
The rag CLI is a global Python 3.13 script at C:\Users\Clandesitine\.local\bin\rag
(synced from scripts/rag-capture-v2/rag_capture.py in rag-gateway-mini). It runs
under Git Bash on Windows with default console encoding cp1252. The script prints
status emojis (check mark, package, clipboard) and reads heredoc content from stdin
via sys.stdin.read() in cmd_add and cmd_pipe.

### Problem
Two related failures blocked end-to-end smoke testing of the new
/rag-knowledge-capture-cli auto-save flow. First, every rag add and rag list
invocation crashed with UnicodeEncodeError: 'charmap' codec can't encode character
at the first print statement (draft was actually written to disk first, but the
non-zero exit broke automation). Second, once stdout was fixed, em dash characters
piped in through heredoc bodies got decoded via cp1252 and written to draft files
as mojibake "a-tilde-euro-quote" sequences, corrupting merged summaries.

### Solution
Added an encoding reconfigure block at module load, right after imports, iterating
over (sys.stdin, sys.stdout, sys.stderr) and calling reconfigure(encoding='utf-8')
on each. stdout and stderr use errors='replace' so rare terminals that cannot
render a given glyph still do not crash the script. stdin uses errors='strict' so
real encoding problems on piped input fail loudly instead of silently corrupting
draft content. The try/except catches AttributeError on older Python versions and
ValueError on streams that cannot be reconfigured.

### Key Facts
- Python 3.13 on Windows defaults sys.stdout/stderr/stdin to cp1252 under most shells
- sys.stdout.reconfigure(encoding='utf-8') exists from Python 3.7+ on TextIOWrapper streams
- Fixing only stdout leaves piped heredoc content corrupted because stdin is still cp1252
- Draft files were written with path.write_text(..., encoding='utf-8') so the file layer was fine; the bug lived entirely in stream decoding before write
- errors='strict' on stdin is preferred over 'replace' so encoding bugs surface immediately
- The installed rag at ~/.local/bin/rag is a standalone copy, not a symlink; patches must be synced manually while preserving the shebang line

### Code / Commands
```python
for _stream, _err in ((sys.stdin, "strict"), (sys.stdout, "replace"), (sys.stderr, "replace")):
    try:
        _stream.reconfigure(encoding="utf-8", errors=_err)
    except (AttributeError, ValueError):
        pass
```

### Caveats
~/.local/bin/rag is a separate copy of the script (different shebang line pointing
at WindowsApps python3). After editing scripts/rag-capture-v2/rag_capture.py, rebuild
the installed rag with: preserve line 1, replace lines 2-end from the repo script,
then retest with rag list to confirm emojis render without crashing.
