## CHUNK 1: rag-knowledge-capture-cli Skill Auto-Save via rag CLI

### Context
The /rag-knowledge-capture-cli skill converts a Claude Code session into embeddable
knowledge chunks for Qdrant collection knowledge_v2 on VM B1. Before this rework,
the project-level skill at .claude/skills/rag-knowledge-capture-cli/SKILL.md
instructed Claude to generate markdown chunks and use the Write tool to land files
in .claude/summaries/. It also targeted the old collection name "knowledge" and
did not use the rag CLI at all.

### Requirements
- Zero manual copy/paste: invoking /rag-knowledge-capture-cli must produce a final
  .md file in .claude/summaries/ with no user intervention
- Delegate all file I/O and frontmatter generation to rag_capture.py via the rag CLI
- Target Qdrant collection knowledge_v2 (new hybrid dense+sparse on VM B1)
- Forbid Claude from printing chunk bodies as chat markdown for copy/paste
- Forbid fallback to the Write tool even when rag command is missing

### Architecture Decision
Keep chunk content generation inside Claude since only Claude has session context,
but delegate all persistence to rag_capture.py. Each chunk body is piped via bash
heredoc into a separate rag add invocation. A final rag merge consolidates drafts
from ~/scripts/.rag_drafts/ into .claude/summaries/YYYY-MM-DD-topic.md. This keeps
the Python script as single source of truth for frontmatter schema, draft numbering,
SESSION METADATA formatting, and push reminder output.

### Implementation
Rewrote .claude/skills/rag-knowledge-capture-cli/SKILL.md with an EXECUTION MODE
block at the top banning three wrong behaviors: printing chunks as chat markdown,
instructing the user to paste, and using the Write tool. Added Step 1 (rag add
per chunk via heredoc) and Step 2 (rag merge). Body templates for the six
chunk_type values now start directly at the Context section since save_draft
at rag_capture.py line 229 auto-prepends a CHUNK header from --topic. Added a
warning box stating the heredoc body must not include a CHUNK header line to
avoid duplication. Mirrored the same edits into the global fallback file at
~/.claude/commands/rag-knowledge-capture-cli.md.

### Key Facts
- Project-level skill at .claude/skills/rag-knowledge-capture-cli/SKILL.md overrides global command with the same name
- save_draft at rag_capture.py line 229 prepends the CHUNK N header from --topic flag; heredoc body must not duplicate it
- rag merge writes to detect_project_root joined with summaries_subdir from config, defaulting to .claude/summaries
- rag merge auto-clears drafts when stdin is non-tty, leaving a clean state after Claude Bash tool runs it
- Collection knowledge_v2 uses named vectors so all Qdrant API calls must pass using=dense or using=sparse explicitly
- Fallback when rag command is missing: call python scripts/rag-capture-v2/rag_capture.py add with the same flags; never fall back to the Write tool
- Use a unique heredoc terminator like RAGBODY_EOF when the body contains example code blocks that include the word CONTENT

### Code / Commands
Invocation pattern (pseudo):
    cat heredoc-body | rag add -p PROJECT -t TYPE --topic "..." --tags "..."
    rag merge --output YYYY-MM-DD-slug.md

### Lessons Learned
Two subtle defects surfaced only during end-to-end smoke testing, not from reading
the skill text: Windows cp1252 stdin corruption of em dashes, and a duplicated
CHUNK header when the body included it. Always run a clean smoke test with
rag clear, one rag add, and rag merge, then grep the merged file for exactly
one CHUNK header line and zero mojibake byte sequences. Also pick a heredoc
terminator that cannot appear verbatim inside the body; generic terminators
like CONTENT clash with example snippets that reference the same word.
