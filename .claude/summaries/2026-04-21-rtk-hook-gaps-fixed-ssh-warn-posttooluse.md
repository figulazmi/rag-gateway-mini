## CHUNK 1: RTK hook gaps fixed: SSH warn PostToolUse + Grep full-param rewrite

### Context
Claude Code on Windows uses custom hooks in ~/.claude/hooks/ to enforce RTK token savings. Two gaps remained after initial rtk-prefix.py and rtk-enforce.py install: SSH body commands bypass rewriting, and Grep deny messages lost tool params.

### Problem
1. SSH body strings (ssh user@host 'cat file') bypass PreToolUse hook -- hook sees outer ssh command but inner body string is never rewritten. VM B1 commands ran raw without RTK.
2. rtk-enforce.py Grep deny only reconstructed pattern/path/glob/-i, losing output_mode, -A/-B/-C, context, multiline, head_limit, offset, -n, type params. Claude had to manually reconstruct the full command.

### Solution
Fix 1 -- Created ~/.claude/hooks/rtk-ssh-warn.py as PostToolUse Bash hook. Checks if command contains "ssh" AND output line count > 30, then prints RTK WARN to stderr with usage example. Always exits 0. Wired in settings.json PostToolUse[matcher=Bash].

Fix 2 -- Rewrote _grep_redirect() in rtk-enforce.py to reconstruct ALL Grep tool params into deny message. Maps: output_mode=files_with_matches to -l, output_mode=count to rg -c (rtk grep lacks -c), context/-C priority over separate -A/-B, glob to --glob, type to --type, multiline to -U --multiline-dotall, head_limit to | head -N pipe, offset to | tail -n +N pipe, quote-escaping single quotes in pattern.

### Key Facts
- PostToolUse hook for Bash fires after every Bash tool call -- check tool_name=="Bash" and tool_input.command contains "ssh" to filter
- output_mode=count must use rg -c not rtk grep -c (rtk grep does not support count output mode)
- context key takes priority over -C key; -C takes priority over separate -A and -B keys
- offset N translates to tail -n +(N+1) in pipe (tail is 1-indexed, offset is 0-indexed)
- Single-quote escape in bash: pattern.replace("'", r"'\''") -- wraps around the apostrophe
- 27/27 regression tests in test-rtk-prefix.py still pass after all changes
- SSH warn threshold is 30 output lines -- below that, chatty SSH is assumed to be direct commands not unfiltered file reads
- settings.json PostToolUse array can have multiple matchers (Write already existed, Bash added alongside)
