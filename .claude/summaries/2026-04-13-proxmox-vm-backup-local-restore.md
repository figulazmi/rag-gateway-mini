## CHUNK 1: Backup VM B1 via vzdump and Download to Local PC

### Context
VM B1 (Ubuntu Server, Proxmox VM ID 100, IP 192.168.18.169) runs the full homelab
AI stack. vzdump creates portable .vma.zst files for disaster recovery and migration
to a new physical Proxmox server.

### Prerequisites
- SSH root access to Proxmox host
- Sufficient disk space on Proxmox local storage
- SCP or WinSCP on local PC

### Steps
1. SSH into Proxmox host as root
2. Check VM ID: `qm list`
3. Create backup: `vzdump 100 --mode snapshot --compress zstd --storage local`
4. Output: `/var/lib/vz/dump/vzdump-qemu-100-YYYY_MM_DD-*.vma.zst`
5. Download to PC (Git Bash): `scp root@<PROXMOX-IP>:/var/lib/vz/dump/vzdump-qemu-100-*.vma.zst C:/Users/Clandesitine/Backups/`

### Verification
- File exists in /var/lib/vz/dump/ with .vma.zst extension
- Proxmox UI: local -> Backups shows the new entry

### Key Facts
- .vma.zst is portable - restoreable on any Proxmox VE host (same or newer version)
- VM ID 100 = B1 - confirm with `qm list` before running vzdump
- --mode snapshot: backup while VM is running, no downtime
- --compress zstd: best compression ratio
- Proxmox backup Notes field limit: 1024 characters - keep notes concise
- Proxmox UI alternative: Datacenter -> Backup -> Add for scheduled automated backups
- vzdump filename is system-generated and cannot be renamed - use Notes field for labeling

### Troubleshooting
- "No space left": run `df -h` on Proxmox host, delete old backups first
- "VM not found": verify VM ID with `qm list`

## CHUNK 2: Restore VM B1 Backup on New Physical Proxmox Server

### Context
After migrating to a new physical server with fresh Proxmox VE, restore VM B1 from
a .vma.zst backup file. This recovers full VM state including OS, Docker, all services,
and data volumes.

### Prerequisites
- Fresh Proxmox VE installed on new server
- .vma.zst backup file on local PC
- Network access to new Proxmox host

### Steps
1. Upload backup to new host: `scp C:/Users/Clandesitine/Backups/vzdump-qemu-100-*.vma.zst root@<NEW-PROXMOX-IP>:/var/lib/vz/dump/`
2. Check available storage: `pvesm status`
3. Restore VM: `qmrestore /var/lib/vz/dump/vzdump-qemu-100-*.vma.zst 100 --storage local-lvm`
4. Start VM: `qm start 100`
5. Verify Tailscale reconnects automatically after boot
6. Verify Docker services: `ssh figulazmi@<VM-IP> "docker ps"`

### Verification
- `qm list` shows VM 100 running
- `curl http://<VM-IP>:5200/health` returns 200 (rag-gateway)
- `curl http://<VM-IP>:3010` returns Token Monitor dashboard
- Tailscale IP 100.120.249.99 accessible from external

### Key Facts
- qmrestore storage target must exist on new host - use `pvesm status` to list options
- VM ID can be changed at restore time: `qmrestore ... 101` if 100 is already taken
- Tailscale reconnects automatically after boot - no reconfiguration needed
- Network IP inside VM stays the same after restore - check for conflicts in new LAN
- Docker containers auto-start if configured with `restart: always` or `unless-stopped`
- Proxmox UI alternative: local -> Backups -> select file -> Restore (GUI wizard)

### Troubleshooting
- "Storage not found": replace local-lvm with correct name from `pvesm status`
- VM boots but no network: LAN IP 192.168.18.169 may conflict with new network range
- Docker containers not running: SSH in and run `docker compose up -d` from /opt/homelab/ai-stack/
