## CHUNK 1: RAG bottleneck fixes P1.2 P3.1 P3.2 P3.3 deployed

### Context
rag-gateway-mini on VM B1. Four bottlenecks from RAG_V2_ROADMAP.md addressed in one session: P1.2 contextual retrieval deployed to n8n, P3.1 supersede semantics added to push-to-qdrant.sh, P3.2 eval set already at 29 queries via fixture file, P3.3 revision queue feedback loop added to eval script.

### Problem
P1.2 was coded in ingest-knowledge-v2.json but n8n on VM B1 had the old workflow (raw content embedding, no contextual prepend). P3.1 had no mechanism to deprecate old chunks when a superseding chunk was pushed. P3.3 had no feedback loop to surface low-NDCG queries for revision. P3.2 eval saturated at Hit@1=1.0 with only 7 queries.

### Solution
P1.2: imported updated workflow via `docker exec n8n n8n import:workflow`, repaired n8n SQLite database (missing shared_workflow entries for 2 workflows, NULL activeVersionId for knowledge_v2), activated via REST API `POST /api/v1/workflows/{id}/activate`. Re-ingested all .claude/summaries/*.md (9 chunks, all 200 OK). n8n now builds embed_content = "This chunk is from project {p}, type {t}, topic '{topic}', tagged {tags}. Session date {date}. Content: {content}" before Ollama embedding.
P3.1: push-to-qdrant.sh reads `supersedes` frontmatter field, converts string ID to djb2 numeric via Python one-liner, PATCHes old Qdrant point status to deprecated with superseded_by set to new doc ID.
P3.3: _write_revision_queue() added to eval-retrieval-quality.py - appends low-NDCG queries (< 0.6) to ~/scripts/.rag_revision_queue.md after each eval run.

### Key Facts
- n8n 2.15 requires activeVersionId = versionId for workflow activation; NULL activeVersionId causes silent skip during Start Active Workflows
- n8n import:workflow deactivates webhook workflows by security design; must activate via REST API POST /api/v1/workflows/{id}/activate after import
- n8n API key stored in user_api_keys.apiKey column in database.sqlite (use when X-N8N-API-KEY header needed)
- push-to-qdrant.sh supersede: djb2 numeric ID computed via python3 inline script matching n8n/C# algorithm exactly
- P3.2 eval set: 7 inline TEST_SUITE + 22 in scripts/eval-fixtures/implementation-tests.json = 29 total; load_json_fixtures already wires the directory
- Contextual prepend (P1.2) expected to reduce retrieval failure 35-49% per Anthropic benchmark; prior chunks re-ingested with new embed_content
- n8n shared_workflow table uses projectId (not userId) in n8n 2.x; project_relation links userId to projectId
