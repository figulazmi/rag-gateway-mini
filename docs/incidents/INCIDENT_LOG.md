# Incident Log

Use this file for production-impacting failures, security events, data loss, severe regressions, or repeated operational issues.

Normal completed changes belong in [`../history/CHANGELOG.md`](../history/CHANGELOG.md).

---

## Incident Entry Format

```markdown
## INC-YYYYMMDD-001 - Short title

| Field | Value |
|---|---|
| Date | YYYY-MM-DD |
| Severity | Low / Medium / High / Critical |
| Status | Investigating / Mitigated / Resolved / Follow-up |
| Impact | User/system impact |
| Root cause | Confirmed cause, or `Unknown` while investigating |
| Resolution | What fixed or mitigated the issue |
| Evidence | Logs, commands, monitoring, PR, or commit |
| Follow-up tasks | TASK-ID or `None` |
```

## Post-Incident Checklist

- Capture user/system impact.
- Identify root cause or state what remains unknown.
- Link evidence.
- Add follow-up tasks to the owning canonical tracker.
- Add a changelog entry if the fix is notable.
